# 메일로 받은 계정 삭제 요청 처리 절차 (#778)

계정 삭제 안내 페이지(`docs/legal/account-deletion.md`) 2절과 처리방침 4절·6절·9절은 "앱 없이 메일로 요청하면 삭제한다"고 안내한다. 이 문서는 그 요청을 운영자가 처리하는 방법이다.

- 대상: 앱을 설치하지 않았거나 로그인할 수 없는 사용자, 가입(닉네임 설정)을 마치지 않아 앱에서 탈퇴할 수 없는 계정
- 도구: `functions/scripts/deleteAccountByEmail.js` — 앱 탈퇴(`deleteAccount`)와 같은 함수(`functions/accountDeletion.js`의 `deleteUserData`·`deleteAuthUser`)로 **같은 범위**를 지운다 (지우는 것·익명화하는 것은 계정 삭제 안내 3절과 같다)
- 순서: 접수 → 본인 확인 → 대상 확인(dry-run) → 실행 → 회신

> ⚠️ Firebase 프로젝트는 `plant-82b09` 하나뿐이고 이것이 운영 환경이다. 스크립트는 실제 계정과 데이터를 지우며 되돌릴 수 없다 (복원은 `docs/FIRESTORE_BACKUP.md`의 백업뿐이고, 계정 하나만 되살리는 절차는 없다).

## 1. 준비 (처음 한 번)

1. 메인 폴더에서 함수 패키지를 설치한다 (스크립트가 `firebase-admin`을 쓴다)

```powershell
npm --prefix functions ci
```

2. 서비스 계정 키를 받는다: Firebase 콘솔 > 프로젝트 설정 > 서비스 계정 > "새 비공개 키 생성"
   - 받은 JSON 파일은 **레포 밖**(예: 사용자 폴더의 별도 폴더)에 둔다. 레포 안에 두거나 커밋하지 않는다 (이 파일 하나로 운영 DB 전체를 읽고 쓸 수 있다)
   - 다 쓰고 나면 Google Cloud 콘솔 > IAM 및 관리자 > 서비스 계정 > 해당 계정 > 키 탭에서 그 키를 삭제하고 파일도 지우는 것을 권장한다 (요청이 올 때마다 새로 받는다)
3. 연습은 에뮬레이터로 먼저 한다 (아래 7절)

## 2. 접수

- 받는 곳: 처리방침 12절·계정 삭제 안내 4절의 문의 메일
- 제목은 "Plant 계정 삭제 요청"으로 안내했지만, 제목이 달라도 삭제를 요청하는 메일이면 처리한다
- 처리는 지체 없이 한다 (계정 삭제 안내 2절 3번)
- 신고·제보 내용 속 개인정보 삭제 요청이 함께 있으면 6절도 처리한다

## 3. 본인 확인

아래를 **모두** 만족할 때만 실행한다. 하나라도 아니면 실행하지 않고 5절 "본인 확인 불가" 회신을 보낸다.

| 확인 | 방법 | 이유 |
|------|------|------|
| 보낸 사람 주소 = 계정 이메일 | 메일의 보낸 사람 주소를 dry-run 출력의 `이메일`과 글자 그대로 비교 | 계정 삭제 안내 2절: "해당 주소에서 보낸 메일만 처리" |
| 발신 인증 통과 | Gmail 웹에서 메일을 열고 ⋮ > "원본 보기" → 위쪽 표의 SPF·DKIM·DMARC가 모두 `PASS`인지 확인 | 보낸 사람 주소는 위조할 수 있다. DMARC `PASS`는 인증한 도메인이 보낸 사람 주소의 도메인과 맞는다는 뜻이다 |
| 회신 주소가 같음 | "원본 보기"에 `Reply-To`가 있으면 보낸 사람 주소와 같은지 확인 | 다르면 결과를 엉뚱한 사람에게 보내게 된다. 회신은 항상 보낸 사람 주소로 한다 |

- "원본 보기" 화면 이름·위치는 Gmail 화면 기준이며, 이 문서를 쓸 때 실제 요청 메일로 확인하지는 않았다 (미확인). 화면이 다르면 메일 헤더의 `Authentication-Results` 줄에서 `spf=pass`, `dkim=pass`, `dmarc=pass`를 찾는다
- Google 계정을 잃어 그 주소로 메일을 보낼 수 없다는 요청: 다른 주소에서 온 요청은 처리하지 않는다. 먼저 [Google 계정 복구](https://accounts.google.com/signin/recovery)로 계정을 되찾은 뒤 그 주소로 다시 보내 달라고 회신한다 (5절 "계정 분실" 회신). 계정 삭제 안내 2절·처리방침 4절·6절이 이렇게 안내한다
  - 다른 확인 방법(닉네임·화분 이름·가입 시기 등)을 두지 않은 이유: 닉네임은 커뮤니티에 공개되어 있어 남이 알 수 있고, 잘못 확인하면 남의 계정을 되돌릴 수 없게 지운다. Google 계정 복구는 Google이 본인 확인을 한다
  - 복구하지 못하면 메일로는 삭제할 수 없다. 그 계정은 아무도 로그인할 수 없으므로 데이터는 그대로 남는다

## 4. 실행

메인 폴더의 `functions` 폴더에서 실행한다. 키 파일 경로는 실제 위치로 바꾼다.

```powershell
cd functions
```

```powershell
$env:GOOGLE_APPLICATION_CREDENTIALS = "C:\경로\키파일.json"
```

### 가. 대상 확인 (dry-run, 아무것도 지우지 않음)

```powershell
node scripts/deleteAccountByEmail.js --project plant-82b09 --email 보낸사람@gmail.com --dry-run
```

출력 예 (값은 계정마다 다르다):

```
접속 대상: 운영 서버 / 프로젝트: plant-82b09
삭제 대상 계정:
  uid          : ...
  이메일       : 보낸사람@gmail.com
  로그인 방식  : google.com
  계정 생성    : ...
  최근 로그인  : ...
  가입 상태    : 가입 완료
  닉네임       : ...
  화분 2개 · 게시글 1개 · 댓글 3개
dry-run: 아무것도 지우지 않았습니다.
```

- `접속 대상`이 `운영 서버`이고 프로젝트가 `plant-82b09`인지 본다 (에뮬레이터 환경 변수가 남아 있으면 `에뮬레이터`로 나온다)
- `이메일`이 보낸 사람 주소와 같은지 3절대로 비교한다
- `가입 상태`는 셋 중 하나다. 어느 것이든 그대로 진행한다 (있는 데이터만 지우고 Auth 계정을 지운다)
  - `가입 완료`
  - `users 문서는 있으나 닉네임 설정 전 (가입을 마치지 않음)`
  - `users 문서 없음 (가입을 마치지 않음)` — 첫 로그인 직후 앱을 닫았거나, 지난 실행이 users 문서까지 지운 뒤 끊긴 경우
- `계정 없음: ...`이 나오면(종료 코드 2) 아무것도 지우지 않은 것이다 → 5절 "계정 없음" 회신. 이미 삭제된 계정에 다시 실행해도 이렇게 나온다
  - 주소에 점(.)·대소문자 차이가 있어도 같은 Gmail 계정일 수 있다. 계정 없음이 나오면 회신으로 Plant에 로그인할 때 고른 Google 계정 주소를 다시 확인해 달라고 한다 (에뮬레이터에서는 대문자가 섞인 주소로 만든 계정이 소문자로 저장되고, 대소문자를 바꿔 찾아도 같은 계정이 나왔다. 운영 Auth의 동작과 점(.) 차이는 미확인)

### 나. 실제 삭제

`--dry-run`을 빼고 같은 명령을 실행한다.

```powershell
node scripts/deleteAccountByEmail.js --project plant-82b09 --email 보낸사람@gmail.com
```

- 대상 계정을 다시 보여 준 뒤 uid 입력을 받는다. 화면의 uid를 **그대로** 입력해야 진행된다 (다른 값을 넣으면 "취소"로 끝나고 아무것도 지우지 않는다, 종료 코드 3)
- `삭제 완료: <uid> (Auth 계정·users 문서 없음 확인)`이 나오면 끝이다 (종료 코드 0)
- `실패: ...`(종료 코드 1)가 나오면 **같은 명령을 다시 실행**한다. 모든 단계가 다시 실행해도 안전하고, Auth 계정은 마지막에 지우므로 같은 이메일로 다시 찾아 남은 단계부터 이어서 처리된다
- 실행하면 앱 탈퇴 때와 같이 Firestore 트리거(화분 삭제 `onPotDeleted`, 댓글 수 `syncCommentCount*` 등)도 실행된다

### 다. 끝나면

```powershell
Remove-Item Env:GOOGLE_APPLICATION_CREDENTIALS
```

- 키 파일을 지우고, 1절 2번대로 콘솔에서 키를 삭제한다

## 5. 회신

회신은 요청 메일에 답장으로 보낸다 (보낸 사람 주소로). uid는 회신·이슈·레포에 적지 않는다.

**삭제 완료**

> 요청하신 Plant 계정과 데이터를 삭제했습니다. 삭제되는 데이터와 개인을 알아볼 수 없는 형태로 남는 데이터는 계정 삭제 안내(https://plant-82b09.web.app/account-deletion.html) 3절과 같습니다. 장애 복구용 백업에는 최대 7일 동안 남을 수 있으며 이후 자동으로 삭제됩니다.

**계정 없음**

> 이 주소로 가입한 Plant 계정을 찾지 못했습니다. 이미 삭제되었거나 다른 Google 계정으로 로그인하셨을 수 있습니다. Plant에 로그인할 때 고른 Google 계정의 주소에서 다시 보내 주세요.

**본인 확인 불가** (주소 불일치·발신 인증 실패)

> 본인 확인을 위해 Plant에 로그인할 때 사용한 Google 계정의 이메일 주소에서 보낸 요청만 처리합니다. 해당 주소에서 다시 보내 주세요.

**계정 분실** (그 주소로 보낼 수 없다는 요청)

> 본인 확인을 위해 Plant에 로그인할 때 사용한 Google 계정의 주소에서 보낸 요청만 처리합니다. Google 계정 복구(https://accounts.google.com/signin/recovery)로 계정을 되찾은 뒤 그 주소에서 다시 보내 주세요. 복구한 뒤에는 앱에서 직접 탈퇴하실 수도 있습니다.

## 6. 신고·제보 내용 속 개인정보 삭제 요청

신고 상세 내용(`reports`의 `detail`)이나 버그 제보·개선 제안 내용(`feedbacks`의 `description`, `reproductionSteps`)에 직접 적은 개인정보는 탈퇴해도 지워지지 않는다 (처리방침 3절 나 ※, 계정 삭제 안내 3절 나). 요청이 오면 Firebase 콘솔 > Firestore에서 해당 문서를 찾아 **개인정보 부분만** 지우도록 필드 값을 고친다. 문서 자체나 다른 필드(대상·사유·처리 상태·분류·앱 버전 등)는 신고 검토와 서비스 개선을 위해 그대로 둔다.

| 상황 | 찾는 방법 |
|------|----------|
| 아직 탈퇴 전 (계정 있음) | 3절 본인 확인 → 4절 가의 dry-run으로 uid 확인 → 콘솔에서 `reports`·`feedbacks`를 `reporterId == <uid>`로 걸러 찾는다 |
| 이미 탈퇴함 (앱 탈퇴 또는 이 스크립트) | 탈퇴하면 `reporterId`가 `""`로 바뀌어 uid로 찾을 수 없다. 요청 메일에 적힌 작성 날짜·내용 일부로 찾는다: 콘솔에서 `reporterId == ""`이고 `createdAt`이 그 날짜 범위인 문서를 걸러, 내용을 하나씩 비교한다 (Firestore는 글자 일부로 검색하지 못한다). 신고는 탈퇴 때 새 ID로 옮겨지지만 `createdAt`은 그대로다 |
| 메일에 날짜·내용이 없음 | 찾을 수 없으므로, 작성 날짜와 내용 일부를 알려 달라고 회신한다 |

- 탈퇴 뒤의 요청은 작성자 정보가 없어 본인인지 확인할 수 없다. 개인정보 부분을 지우는 것은 신고·제보의 쓰임을 해치지 않으므로, 메일의 날짜·내용이 문서와 맞으면 처리한다
- 계정 삭제와 함께 요청받았다면 **삭제를 실행하기 전에** 이 절을 먼저 처리한다 (uid로 바로 찾을 수 있다)

## 7. 에뮬레이터로 연습하기

운영에서 처음 실행하기 전에 에뮬레이터에서 같은 순서로 해 본다. 레포 루트에서:

```powershell
firebase emulators:start --only firestore,auth --project demo-plant
```

다른 터미널의 `functions` 폴더에서:

```powershell
$env:FIRESTORE_EMULATOR_HOST = "127.0.0.1:8080"; $env:FIREBASE_AUTH_EMULATOR_HOST = "127.0.0.1:9099"
```

- 에뮬레이터 UI(http://127.0.0.1:4000)의 Authentication에서 이메일이 있는 사용자를 하나 만들고, Firestore에 `users/<uid>` 문서 등을 넣은 뒤 4절 명령을 `--project demo-plant`로 실행한다
- 환경 변수를 둘 중 하나만 넣으면 스크립트가 실행하지 않는다 (Firestore와 Auth가 서로 다른 곳을 가리키게 되므로)
- 끝나면 `Remove-Item Env:FIRESTORE_EMULATOR_HOST, Env:FIREBASE_AUTH_EMULATOR_HOST`로 지운다. 남아 있으면 운영 실행이 에뮬레이터로 간다 (출력의 `접속 대상`으로 확인)

자동 테스트: `functions/test/integration/deleteAccountByEmail.test.js` (가입 완료·미완료·계정 없음·dry-run·입력 불일치·중간 실패 후 재실행), `functions/test/unit/deleteAccountByEmailArgs.test.js` (인자·접속 대상). `npm --prefix functions test`로 실행한다.

## 8. 주의

- Firebase 콘솔의 Authentication에서 계정을 **먼저 지우지 않는다.** Auth 계정이 없으면 스크립트가 이메일로 uid를 찾을 수 없어 Firestore 데이터가 남는다 (이 스크립트는 uid로 직접 지우는 방법을 두지 않았다)
- 탈퇴 범위(`functions/accountDeletion.js`)를 바꾸면 앱 탈퇴와 이 스크립트에 함께 반영된다. 이때 계정 삭제 안내 3절·처리방침 3절도 함께 고친다 (`docs/LEGAL_HOSTING.md` 문서 수정 절차 4번)
- 스크립트(`functions/scripts`)는 함수 배포에 포함되지 않는다 (`firebase.json`의 `functions.ignore`)
